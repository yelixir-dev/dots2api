# Execution and resource contracts

## Submission and ownership

- Dots and Muse never automatically replay accepted or uncertain work.
  Authentication recovery alone is not proof that earlier execution did not happen.
- Dots may retry one correlated, structured pre-execution missing-thread RPC rejection
  when there is no contradictory same-thread activity. Error prose and failed accepted
  turns cannot authorize a retry.
- A selected Dots thread must report Aeon provenance, or carry the gateway's durable
  `self` ownership marker. Rotation preserves this marker and never archives the
  operator's original thread.
- A job and an interactive login/check cannot own an account simultaneously. Login
  completion is single-flight through connection verification. Cancel/complete
  conflicts return 409; old callbacks and sockets cannot affect a new generation.
- On Linux, Xvfb allocates an owned display through `-displayfd`, not an existence
  check on another process's socket. A private writable X11 socket directory is
  required; a read-only WSLg socket mount is not a suitable validation environment.
- Shutdown stops admission, aborts/drains pending launches, finalizes accepted queues
  and closes SQLite last. Restart recovery records unknown work and account
  quarantine in one transaction.

## Image results and JSON

- Later image admission failures return earlier completed images and their job IDs.
- Dots reconciles missing image items from the turn list and merges by remote item ID.
  All observed generated bytes count toward thread accounting, even when only eight
  images are returned. Reference bytes count once. Unknown image bytes mark accounting
  incomplete and force rotation before another job uses that thread.
- The 8 MiB thread rotation threshold is an operational heuristic, not a proven
  provider context limit.
- An explicit `output_format` returns 422 before generation. Omitting it returns
  the actual provider encoding; this gateway does not transcode images.
- Tool arguments with unsafe integer tokens are rejected instead of rounded into
  different identifiers. Ordinary JavaScript floating-point fractions remain supported.
  Arbitrary JSON own keys, including nested `__proto__`, are preserved without
  changing object prototypes.

## Local budgets

These are local retention/transport quotas, not upstream model limits or total RSS
guarantees.

| Resource | Bound |
| --- | --- |
| Accepted jobs per account, running plus queued | 20 |
| Retained input quota across accounts | 128 MiB by default |
| Quota accounting | UTF-16 prompt bytes plus raw reference bytes |
| Reference upload | 8 files, 32 MiB combined; 33 MiB multipart body |
| Generated images retained per provider run | 32 MiB combined |
| Public generated-image list | 8 images |
| Muse worker stdin / one stdout JSON line | 64 MiB |
| Retained worker stderr suffix | 256 KiB |
| Dots one inbound frame / queued notification bytes | `4 * ceil(32 MiB / 3) + 1 MiB` |
| Dots received bytes per connection | Four frame budgets |
| Dots queued / total notification count | 256 / 4096 |
| Worker graceful termination / final wait cutoff | 5 seconds / 10 seconds |
| Worker diagnostic pipe cancellation cutoff | 2 seconds |
| Media fetch / Xvfb readiness deadline | 30 seconds / 10 seconds |

`DOTS2API_QUEUE_BYTES` accepts integer bytes, with a minimum of 41943040 (40 MiB).
Invalid values fail startup. Exhaustion returns `429 queue_bytes_full` before
allocating another reference snapshot or persisting a job. Job completion, failure,
abandonment and shutdown each release that job's reservation once.

For a systemd installation, set a service drop-in with `systemctl --user edit dots2api`:

```ini
[Service]
Environment=DOTS2API_QUEUE_BYTES=134217728
```

The default deliberately does **not** promise four maximum edits: four 32 MiB
reference payloads already consume 128 MiB before nonempty prompts. Three such
edits fit with headroom; the 40 MiB floor allows one maximum edit. Count quotas
still apply independently to smaller jobs.

Base64 uses `4 * ceil(raw_bytes / 3)` bytes before JSON overhead. Download buffers,
decoded outputs, database reads, HTTP responses, Chromium, Node and Xvfb require
additional memory beyond the queue quota. Choose a service RSS/cgroup limit from
measurements on the deployment machine; no minimum-host-RAM or OOM-free guarantee
is inferred from these constants. The Linux validation host had 3917 MiB total
memory and approximately 3420 MiB available before checks, not a measured
production capacity for concurrent image generation.

## Verification

Regression tests use event-controlled local HTTP/WebSocket/browser fixtures, real
SQLite transactions with injected write faults, bounded streams and a controlled
termination scheduler. `tests/muse-ownership.test.ts` additionally starts concurrent
real Xvfb processes on Linux and checks that stopping one leaves the other usable.
Live provider compatibility and billing/quota behavior require separate authorized
provider calls; local fixture success does not establish either.
